# Плагин router-llama для OpenCode

## Краткое описание

Плагин интегрирует llama.cpp router в OpenCode, позволяя удобно управлять загрузкой/выгрузкой моделей и автоматически подставлять выбранную модель в текущий чат.

## Как использовать

### Предварительные требования

1. Установлен и запущен llama.cpp сервер в режиме роутера с флагами:
   - `--models-preset` — использовать пресеты из конфига
   - `--models-max 1` — одновременно загружается только одна модель

2. Пример конфигурации (`opencode.jsonc`):
   ```json
   {
     "provider": {
       "router-llama": {
         "npm": "@ai-sdk/openai-compatible",
         "name": "router-llama",
         "options": {
           "baseURL": "http://127.0.0.1:9931/v1",
           "apiKey": "ваш_ключ_здесь"
         }
       }
     }
   }
   ```

### Основные команды

- `/router-llama` — открыть диалог выбора модели и загрузить её
- `/router-llama <имя_модели>` — загрузить модель по имени (без диалога)
- В диалоге нажмите `Ctrl+U` — выгрузить выбранную модель

### Как это работает

1. Запустите команду `/router-llama`
2. В диалоге выберите нужную модель из списка
3. Модель автоматически загрузится в роутер
4. Чат переключится на выбранную модель
5. Если модель уже загружена — только переключится на неё

### Статусы моделей в списке

- `в памяти` — модель загружена и готова к работе
- `не загружена` — модель не загружена
- `загружается` — модель загружается сейчас
- `спит (в памяти)` — модель загружена, но находится в спящем режиме
- `сбой` — модель не смогла загрузиться (смотрите код выхода)

## Принцип действия

### Архитектура

Плагин состоит из двух частей:

1. **Серверная часть (`index.ts`)** — работает в фоновом режиме OpenCode
2. **TUI-часть (`tui.ts`)** — обеспечивает интерфейс взаимодействия с пользователем

### Серверная часть

Серверная часть выполняет следующие задачи:

1. **Чтение конфигурации** — читает `opencode.jsonc` для получения настроек роутера и "local" провайдера
2. **Регистрация провайдера** — добавляет в реестр провайдер `router-llama` со списком всех доступных моделей (включая незагруженные)
3. **Снижение лимитов** — уменьшает `context` и `output` лимиты для модели `local/loaded-gguf` до значений, поддерживаемых сервером
4. **Регулярный опрос** — каждые 20 секунд опрашивает роутер на предмет изменений статусов моделей и обновляет реестр
5. **Инструмент для агентов** — предоставляет инструмент `router_llama_list` для получения списка моделей и их статусов

### TUI-часть

TUI-часть обеспечивает удобный интерфейс:

1. **Команда `/router-llama`** — открывает диалог выбора модели
2. **Автоматическая загрузка** — при выборе модели отправляет запрос `POST /models/load` в роутер
3. **Ожидание завершения** — ждёт статуса "loaded" или "sleeping" (до 5 минут)
4. **Переключение чата** — после успешной загрузки переключает текущую сессию на новую модель
5. **Автоматическая перезагрузка** — если модель была выгружена извне, плагин автоматически загружает её при следующем обращении
6. **Выгрузка по Ctrl+U** — позволяет выгрузить выбранную модель из памяти

### Взаимодействие с роутером

Плагин использует API роутера:

- `GET /models` — получение списка всех моделей и их статусов
- `POST /models/load` — загрузка модели
- `POST /models/unload` — выгрузка модели
- `GET /health` — проверка состояния сервера "local" (для определения `max_context`)

### Обработка ошибок

- При провале загрузки показывается код выхода из ответа роутера
- Если загрузка не завершается в течение таймаута — отображается соответствующее сообщение
- Если чат не переключается, показывается предупреждение
